## 2. Транспорт и сеть

1. Все запросы к VK API идут через axios **с SOCKS5-прокси tor `127.0.0.1:9050`** (31.03, L31214). Адрес и порт берутся из конфига; **ДОПУЩЕНИЕ**: ключ `vk.proxy` в `config.json`, по умолчанию `socks5h://127.0.0.1:9050`, пустое значение выключает прокси.
2. Причина: 31.03 сервер получил капчу и бан по IP за «701 перезапуск за несколько часов» и «100% CPU VK-запросами» (L31224, L31220–31232, L31322–31343). Отсюда требования:
   - лимит запросов к API (**ДОПУЩЕНИЕ**: очередь не больше 3 запросов в секунду, это лимит VK для пользовательского токена);
   - при ошибке капчи (`error_code 14`) нужен бэкофф без мгновенного рестарта процесса (**ДОПУЩЕНИЕ**: пауза от 60 секунд с ростом);
   - защита от цикла перезапусков (**ДОПУЩЕНИЕ**).
3. Предупреждение 01.04: «за лп банят аккаунт ВК навсегда» (L31351). Это риск владельца, в коде его не обходим.

## 3. Авторизация

1. Токен пользователя VK вида `vk1.a...` (01.04, L31406; это ответ другого бота, формат токена тот же).
2. Команда `*вк_токен [token]` устанавливает VK-токен (03.04, L34211). Токен хранится в конфиге или в БД, **не в коде**. Ключ `vkUserToken` в `config.json` удалён (коммит `80239ab`), поэтому **ДОПУЩЕНИЕ**: env `VK_USER_TOKEN` с приоритетом, затем `config.json` → `vk.userToken`, затем запись через `*вк_токен`.
3. `*вк_группа [id] [token]` настраивает VK-группу (03.04, L34212). Значит, кроме юзер-клиента предусмотрен ещё групповой токен.
4. VK-клиент стартует независимо от TG и не ждёт TG-авторизации (03.04, L33690).

## 4. Long poll

1. В переписке есть только команда `*вк_лп_статус` — «статус VK LP» (03.04, L34214). Структура long poll в чате **не описана**.
2. **ДОПУЩЕНИЕ** (стандартная схема VK для userbot):
   - `messages.getLongPollServer` с `lp_version=3`, `need_pts=1`;
   - цикл `https://{server}?act=a_check&key=&ts=&wait=25&mode=2&version=3`;
   - `failed=1` → взять новый `ts`; `failed=2/3` → заново `getLongPollServer`;
   - событие `4` (новое сообщение) → нормализовать в объект как у TG (`text`, `peerId`, `fromId`, `messageId`, `out`) и передать в общий обработчик.
3. `*вк_лп_статус` показывает: подключён ли LP, последний `ts`, время последнего события, число ошибок и капч (**ДОПУЩЕНИЕ** по составу полей).

## 5. Обработка сообщений и префикс

1. Префикс в VK — `*` (02.04 и 03.04: «Префикс: *», L33870; в версии от 31.03 был `'`, L31240). Делать настраиваемым, по умолчанию `*`.
2. Проверка префикса обязательна, без неё бот реагировал на всё подряд (02.04, L32946 «нет проверки префикса»).
3. Неизвестная команда → ответ `❌ Команда '*X' не найдена` + `Для TG команд: *тг_X` (02.04, L32855, L32885).
4. Доступ: команды выполняют владелец и доверенные VK-пользователи (02.04, L32858–32868). Ответы:
   - `✅ <Имя> (<id>) добавлен в доверенные`
   - `📋 Доверенные VK пользователи: • Имя ([id…|@screen]) [id]`, затем `Добавить: *доступ добавить @юзер`, `Удалить: *доступ удалить @юзер`
   - баг 02.04: вместо screen_name выводилось `@undefined` и чужой id (L32860). Брать данные через `users.get` с `fields=screen_name`.
5. Без ID → `❌ Укажи ID, @юзернейм или ответь на сообщение` (02.04, L32952).
6. Межплатформенные команды: `*вк_[userId]_[команда]` и `*тг_[userId]_[команда]` (03.04, L34215–34216).

## 8. Устройство модуля (повторяет TG-клиент из `script.js`)

TG-часть: класс `lpbot`, `setupMessageHandlers()` (строки ~1383 и ~1426), там проверка префикса → `handleCommand(command, args, message, chatId, senderId, messageId)` → таблица `this.commands`; триггеры — `handleEnhancedTriggers`; SQLite общий.

**ДОПУЩЕНИЕ** по структуре `vk_client.js`:
- `class VkClient { constructor(bot, config) ; start() ; stop() ; api(method, params) ; pollLoop() ; normalize(update) ; send(peerId, text, opts) ; edit(...) ; delete(...) }`;
- `module.exports = VkClient`; `script.js` создаёт его рядом с `TelegramClient` и запускает без ожидания TG;
- входящие сообщения после `normalize` идут в те же `handleCommand` и `handleEnhancedTriggers`, у которых платформа определяется по полю `platform: 'vk'`, чтобы не дублировать 40 команд;
- база общая (`bot_database.sqlite`), отдельные таблицы под VK-доверенных и настройки LP.

## 9. Критерии приёмки (для Егора и Тимура)

1. `node --check vk_client.js` проходит, `require('./vk_client.js')` без токена не падает и не ходит в сеть.
2. Без токена VK-клиент не стартует, в лог пишет одну строку, TG при этом работает.
3. Все запросы идут через прокси из конфига, это проверяется на заглушке axios-адаптера.
4. При капче (код 14) срабатывает бэкофф, процесс не перезапускается.
5. Префикс `*` проверяется, на неизвестную команду приходит ответ из п. 5.3.
6. `check.sh`: TG-команды, маршруты и обработчики не изменились.
