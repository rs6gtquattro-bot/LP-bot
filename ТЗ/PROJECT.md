### 1.2. Транспорт и сеть

1. Все запросы к VK API идут через axios с SOCKS5-прокси tor `127.0.0.1:9050` (31.03, L31214). Адрес и порт берутся из конфига. **ДОПУЩЕНИЕ**: ключ `vk.proxy` в `config.json`, по умолчанию `socks5h://127.0.0.1:9050`, пустое значение выключает прокси.
2. Причина: 31.03 сервер получил капчу и бан по IP за «701 перезапуск за несколько часов» и «100% CPU VK-запросами» (L31207, L31219, L31329). Отсюда требования:
   - лимит запросов к API (**ДОПУЩЕНИЕ**: очередь не больше 3 запросов в секунду, это лимит VK для пользовательского токена);
   - при ошибке капчи (код 14) нужен бэкофф без мгновенного рестарта процесса (**ДОПУЩЕНИЕ**: пауза от 60 секунд с ростом);
   - защита от цикла перезапусков (**ДОПУЩЕНИЕ**).
3. Предупреждение 01.04: «за лп банят аккаунт ВК навсегда» (L31329). Это риск владельца, в коде его не обходим.

Текущая рабочая схема транспорта (после ветки туннеля) описана в разделе 3: вместо tor используется SSH-туннель до ПК владельца, SOCKS5 `127.0.0.1:1080`.

### 1.3. Авторизация

1. Нужен токен пользователя VK (01.04, L31406).
2. Команда `*вк_токен [token]` устанавливает токен (03.04, L34211). Токен хранится в конфиге или в БД, **не в коде**. Ключ `vkUserToken` в `config.json` удалён (коммит `80239ab`), поэтому **ДОПУЩЕНИЕ**: переменная окружения `VK_USER_TOKEN` с приоритетом, затем `config.json` → `vk.userToken`, затем запись через `*вк_токен`. Правило команды сейчас жёстче: в работе токен задаётся только через `VK_USER_TOKEN`.
3. `*вк_группа [id] [token]` настраивает VK-группу (03.04, L34212). Значит, кроме юзер-клиента предусмотрен ещё групповой токен.
4. VK-клиент стартует независимо от Telegram и не ждёт его авторизации (03.04, L33690).

### 1.4. Long poll

1. В переписке есть только команда `*вк_лп_статус` — «статус VK LP» (03.04, L34214). Структура long poll в чате **не описана**.
2. **ДОПУЩЕНИЕ** (стандартная схема VK для userbot):
   - `messages.getLongPollServer` с `lp_version=3`, `need_pts=1`;
   - цикл `https://{server}?act=a_check&key=&ts=&wait=25&mode=2&version=3`;
   - `failed=1` → взять новый `ts`; `failed=2/3` → заново `getLongPollServer`;
   - событие `4` (новое сообщение) → нормализовать в объект как у Telegram (`text`, `peerId`, `fromId`, `messageId`, `out`) и передать в общий обработчик.
3. `*вк_лп_статус` показывает: подключён ли LP, последний `ts`, время последнего события, число ошибок и капч (**ДОПУЩЕНИЕ** по составу полей).

### 1.5. Обработка сообщений и префикс

1. Префикс в VK — `*` (02.04 и 03.04: «Префикс: *», L32682, L33866; в версии от 31.03 был `'`, L31232). Делать настраиваемым, по умолчанию `*`.
2. Проверка префикса обязательна, без неё бот реагировал на всё подряд (02.04, L32930 «нет проверки префикса»).
3. Неизвестная команда → ответ `❌ Команда '*X' не найдена` + `Для TG команд: *тг_X` (02.04, L32893–32894, L32946–32947).
4. Доступ: команды выполняют владелец и доверенные VK-пользователи (02.04, L32895–32897). Ответы:
   - `✅ <Имя> (<id>) добавлен в доверенные`
   - `📋 Доверенные VK пользователи: • Имя ([id…|@screen]) [id]`, затем `Добавить: *доступ добавить @юзер`, `Удалить: *доступ удалить @юзер`
   - баг 02.04: вместо screen_name выводилось `@undefined` и чужой id (L32897). Брать данные через `users.get` с `fields=screen_name`.
5. Без ID → `❌ Укажи ID, @юзернейм или ответь на сообщение` (02.04, L32937).
6. Межплатформенные команды: `*вк_[userId]_[команда]` и `*тг_[userId]_[команда]` (03.04, L34215–34216).

Сейчас префикс VK берётся из `settings.prefix` (тот же, что у Telegram). В рабочем `settings.example.json` это `‘` (U+2018), а не `*`. Подробности и текущий баг — в разделе 6.

### 1.8. Устройство модуля (повторяет TG-клиент из `script.js`)

В `main.js` остаётся только ядро: отвечает на запрос версии движка, объясняет, как подключать модули, и загружает их.

### 2.3. Формат модуля (`modules/<…>/index.js`)

```js
module.exports = {
  name: 'qr',
  version: '1.0.0',
  engine: '^1.0.0',
  requires: ['messaging', 'telegram'],
  commands: {
    'qr': { handler, help: 'QR из текста', aliases: [] }
  },
  async init(core) {},
  async stop(core) {}
};

// handler(core, { args, message, chatId, senderId, messageId })
```

Новый модуль подключается так: папка кладётся в `modules/`, бот перезапускается. Если модуль сломан или падает в `init`, отключается только он, остальной бот продолжает работать. Модуль с несовместимым `engine` не грузится, это пишется в лог.

### 2.4. API ядра (`main.js`, цель — до 200 строк)

`core.version` берётся из `package.json` и равна `1.0.0`. Версии только X.Y.Z (`^\d+\.\d+\.\d+$`): X — релиз, Y — патчи критических уязвимостей и ошибок, Z — мелкие фиксы.

- `core.provide(name, obj)` и `core.get(name)` — службы: `db`, `settings`, `telegram`, `messaging` (с `editMessage`, `safeDelete`, `splitMessage`) и так далее.
- `core.command(name, handler, meta)` регистрирует команду. Повтор имени даёт ошибку при старте, а не тихую перезапись.
- `core.on(event, fn)` и `core.emit(...)` — события `message`, `ready`, `stop`. Через них работают триггеры, автопуши и мост VK.
- `core.log(module, text)` пишет лог с именем модуля. Секреты в лог не попадают, проверка как в тестах.

Загрузчик обходит `modules/` и выстраивает порядок по `requires`. Переход на модули ничего не открывает к секретам: файловые команды по-прежнему ходят через `secret_files.js`.

Команда `движок` (с текущим префиксом из настроек) отвечает версией движка, списком загруженных и отключённых модулей и короткой инструкцией: «положи папку в `modules/`, экспортируй объект такого формата, перезапусти бота». Ссылку на `docs/modules.md` даёт там же.

**Этап 2** (Егор). Службы `core/*`: база, настройки, сессия, Telegram, процесс. Самый опасный этап: затрагивает вход в Telegram. Отдельный перезапуск, только после бэкапа `session.txt` у Тимура и только по команде Дениса.

**Этап 3** (Роман). Простые команды пачками по 5–6. На первом шаге обработчик получает `core`, а `this.x` заменяется на `core.get(...)`. Логику не переписывать, только переносить.

**Этап 4.** `triggers`, `templates`, `timers` и `code` — по одной ветке на каждую, со своими тестами на заглушках базы.

**Этап 5** (Егор). `vk` и `panel` (тесты `vk_*`, `panel_host` и туннель).

**Этап 6.** `script.js` удаляется, `package.json`, main и `start.bat` переводятся на `main.js`, `check.sh` переписывается под модули.

### 2.6. Голая версия для ПК

`tools/make_bare.sh` собирает только:

- `main.js`
- `package.json`

- `modules/README.md` (формат модуля)
- `docs/modules.md`
- `README.md`

На ПК кладёт Тимур через `pcput.py` в `C:\LP-bare\`. `.gitignore` уже закрывает секреты, на случай если владелец положит туда рабочие файлы.

### 2.7. Риски

Этап 2 трогает вход в Telegram. Если ошибиться, `session.txt` может потребовать новой авторизации, и коды придётся снова просить у владельца. Поэтому этап отдельный, с бэкапом сессии до перезапуска.

Связь через `this` очень плотная: обработчики дёргают друг друга (триггеры шлют реакции, шаблоны удаляют сообщения). Такие вызовы идут через службы; если что-то забыть, тест-слепок и `check.sh` это поймают.

## 3. Архитектура

LP-бот для аккаунта Telegram (GramJS) с VK-клиентом, веб-панелью и необязательным окном GUI на Electron. Точка входа — `script.js` (`npm start` / `node script.js`). В `main` `28534b3`: `script.js` 7372 строки, `vk_client.js` 970, `web_interface.js` 407, `tg_web_dc.js` 28.

### 3.1. Telegram

- Класс `lpbot` в `script.js`, клиент GramJS, сессия в `session.txt` (создаётся после первого входа из консоли).
- Транспорт: WebSocket на `*.web.telegram.org`, порт 443 (`tg_web_dc.js`). Стартовый DC и переходы между DC только по web-именам, голые IP не используются.
- При старте в лог не печатаются API ID и хвост API Hash (только «задан» / «НЕ УСТАНОВЛЕН»).
- Префикс команд — `settings.prefix`. Проверка в обработчике сообщений обычным `startsWith`, без нормализации символов.
- Команды задаются в `setupCommands()`: в `28534b3` 40 имён, включая синонимы (`шаб`/`шаблон`, `код`/`code`, `кастом`/`custom`, `дип`/`deepseek`).
- Межплатформенный мост, только для владельца: из Telegram в VK — `вк_[команда]` или `вк_[peerId]_[команда]` (и только от самого аккаунта).

Первый вход — только из консоли: номер, код из Telegram и при необходимости облачный пароль 2FA. Через GUI первый вход не пройти.

### 3.2. VK-клиент и туннель

- Модуль `vk_client.js`, класс `VkClient`. `script.js` создаёт его при старте и вызывает `start()` сразу, не дожидаясь авторизации Telegram.
- Токен берётся из `VK_USER_TOKEN` (приоритет). Без токена клиент не стартует и пишет в лог одну строку, Telegram при этом работает.
- Long poll: `messages.getLongPollServer` с `lp_version=3`, цикл с `mode=2`, `version=3`, `wait=25`. Событие `4` нормализуется из полей `[4, messageId, flags, peerId, ts, text, extra]`; исходящее — по `flags & 2`.
- Все HTTP-запросы VK, включая long poll, идут через axios и прокси из `vk.proxy`. В работе это `socks5h://127.0.0.1:1080`.
- Лимит: очередь не больше 3 запросов в секунду. Капча (код 14) — бэкофф от 60 секунд с ростом, без рестарта процесса.
- Префикс общий с Telegram: `settings.prefix` передаётся при запуске, при смене префикса и при перечитывании `settings.json`. Проверка: `msg.text.startsWith(prefix)` в `vk_client.js` (строка 296 в `28534b3`), без нормализации и без раскодирования HTML-сущностей.
- Свои сообщения бот правит через `messages.edit`, чужие отвечает через `messages.send`. Ошибки обработки пишутся в лог, молча не глотаются.
- Счётчик событий long poll: в логе строка `📥 VK LP: событий N` (первое и каждое сотое) и в `/api/stats` поля `vkEvents`, `vkConnected` — без текста сообщений.

Токен VK привязан к IP владельца, поэтому трафик бота к VK идёт не напрямую и не через tor, а через SSH-туннель до ПК владельца:

`tools/vk_tunnel.py`: локальный SOCKS5 `127.0.0.1:1080` → SSH (`direct-tcpip`) → ПК владельца → VK.

Белый список только в коде, расширить через окружение нельзя:

- точные имена: `api.vk.com`, `oauth.vk.com`, `lp.vk.com`, `im.vk.com`;
- суффиксы: `.vk.com`, `.vk.ru`, `.userapi.com`;
- отдельно: `nominatim.openstreetmap.org` (геокодинг команды «геолокация»), тоже только порт 443;
- только порт 443;
- имя проверяется строго: каждая часть `[a-z0-9-]`, длина 1–63, без `-` по краям;
- голые IP отклоняются; подделки вида `evil.org` + нулевой байт + `.vk.com`, пробел, «/» — отказ.

Если туннель упал, VK-клиент получает ошибку и напрямую в VK не ходит (`vk_proxy_failclosed`). Telegram туннель не использует. Живой процесс туннеля (tmux-сессия `lpvk`) команда не трогает.

### 3.3. Веб-панель

`web_interface.js`, порт 3001, по умолчанию слушает `127.0.0.1` (`panelHost` в `config.json`). Пароли у панели нет, наружу её не открывают.

Разделы: главная, настройки, триггеры, шаблоны, команды, DeepSeek, логи, статистика, экспорт.

Полезные маршруты:

- страницы: `/`, `/settings`, `/triggers`, `/templates`, `/commands`, `/deepseek`, `/logs`, `/stats`, `/export`;
- `/status`, `/api/stats` (в том числе `vkEvents`, `vkConnected`), `/api/commands`, `/api/settings` (без ключей: префикс и флаги), `/api/templates`, `/api/triggers`, `/api/logs`, `/api/deepseek/test`;
- изменение настроек и DeepSeek — соответствующие POST; удаление шаблонов и триггеров — через API/формы с data-атрибутами (имена с кавычками не ломаются).

Экспорт выгружает в JSON триггеры, шаблоны и безопасные настройки (префикс и флаги). Ключи и сессия в экспорт не попадают. Логи — последние 500 строк консоли бота, только пока он запущен. Ключ DeepSeek в панели показывается замаскированным; сохранение формы с маской ключ не меняет.

GUI (`gui/start_gui.bat`): окно Electron запускает и останавливает `script.js`, показывает лог и берёт команды и настройки у панели `http://127.0.0.1:3001`. Закрытие окна завершает GUI и бота.

### 3.4. Секретные файлы

`secret_files.js` закрывает файловые команды бота (`код …` в Telegram и `код показать` в VK): они не читают, не меняют и не восстанавливают секретные файлы. В список входят: `session.txt`, `*.session`, `config.json`, `settings.json`, `.env`, `.env.*`, `*.sqlite` и `-journal`/`-wal`/`-shm`, короткие имена Windows 8.3 (`~\d`), папка `.git` и бэкапы этих файлов в `backups/`. Регистр букв не важен.

Эти же файлы не коммитятся (см. `.gitignore`) и не входят в архивы `backup.sh`.

## 4. Как запускать и как проверять

### 4.1. Запуск

Рабочая копия — из корня проекта (там же `script.js` и `package.json`). Node.js 18+ (LTS). Зависимости: `npm install`.

Локально для разработки:

```bat
copy config.example.json config.json
copy settings.example.json settings.json
npm start
```

или `node script.js`. Остановить в консоли — Ctrl+C.

В работе бот и туннель крутятся в отдельных сессиях tmux:

- туннель: сессия `lpvk`, процесс `tools/vk_tunnel.py`, SOCKS5 `127.0.0.1:1080`. Если он уже запущен, его не трогают и не перезапускают без команды Дениса;
- бот: сессия `lpbot`, из корня рабочей копии, `node script.js`. Токен VK задаётся только переменной окружения `VK_USER_TOKEN`, в чат и в коммиты он не попадает;
- в рабочем `config.json` у VK должно быть `"proxy": "socks5h://127.0.0.1:1080"`.

Перезапуск бота — только по команде Дениса. Процесс останавливают по PID или через `tmux kill-session -t lpbot`, затем проверяют `ps`/`pgrep`, что старого `node script.js` больше нет. Сервер tmux и сессию `lpvk` не убивают: в том же сервере живёт туннель.

Если в логе капча или ошибка авторизации VK/Telegram — сразу стоп и доклад Денису, процесс не перезапускают по кругу.

### 4.2. Проверки

Тесты запускаются только на Linux (WSL). На Windows их не гоняют. Все тесты, кроме `panel_host`, идут на заглушках и обязаны запускаться без сети, под `unshare -rn`, с снятым токеном VK. В каждом из них первой строкой стоит проверка `tests/_no_network.js`: если у машины есть сетевой интерфейс кроме петли, тест сразу пишет `FAIL сеть доступна` и завершается с кодом 1. Обхода нет. Ручных запросов в VK из тестов и при диагностике нет.

Полный цикл:

```sh
for t in auth trigger-time vk_client vk_commands tg_ws startup_log secret_files vk_proxy_failclosed vk_prefix; do
  env -u VK_USER_TOKEN unshare -rn node tests/$t.test.js
done

env -u VK_USER_TOKEN unshare -rn /workspace/.sshvenv/bin/python tests/vk_tunnel_test.py

node tests/panel_host.test.js

node --check script.js vk_client.js web_interface.js
```

Что проверяет каждый тест:

| Тест | Что закрывает |
|---|---|
| `auth` | ветки входа Telegram: есть сессия / нет сессии (заглушки) |
| `trigger-time` | время и дни триггеров, неизменность разбора времени |
| `vk_client` | критерии приёмки ТЗ п. 1.9 на заглушках axios |
| `vk_commands` | команды VK и мост `вк_` / `тг_` |
| `tg_ws` | Telegram только через `*.web.telegram.org:443`, без голых IP |
| `startup_log` | старт не печатает API ID и хвост API Hash |
| `secret_files` | файловые команды не читают и не меняют секреты |
| `vk_proxy_failclosed` | туннель недоступен — прямого хода в VK нет |
| `vk_prefix` | префикс из `settings.prefix`, счётчик событий LP без текста |
| `vk_tunnel_test.py` | белый список, порт 443, отказ голым IP и поддельным именам |
| `panel_host` | панель по умолчанию слушает только `127.0.0.1` и не принимает подключения с внешнего интерфейса; нужны `node_modules` (express, ws), сеть только к адресам этого компьютера |

`check.sh [commit]` сравнивает указанный коммит с эталоном v0 по файлам: `commands`, `methods`, `routes`, `event_handlers_count`, `duplicate_methods`, `node_check`.

После правок панели дополнительно гоняется smoke-тест Романа: страницы панели, экспорт без мёртвых кнопок, удаление триггеров и шаблонов с кавычкой в имени, на `/commands` видны все команды. Эталон приёмки был 28 из 28, FAILS 0. Его прогоняют на пробном слиянии до merge.

Приёмка правки команд VK — только по факту: в логе обработана реальная команда владельца и ушёл ответ (`messages.edit` или `messages.send`). Счётчика `vkEvents` и строки «клиент запущен» недостаточно.

## 5. Правила команды и процесс

Руководитель — Денис. Новую задачу команда берёт только с его разрешения (и с разрешения владельца, когда это его решение). Отсебятина и отклонение от ТЗ возвращаются в работу.

### 5.1. Роли

- **Денис** — руководитель: ставит ТЗ, сроки, критерии приёмки, принимает или отклоняет результат. Код и файлы сам не меняет.
- **Егор** — бэкенд и сеть: пишет код в своих ветках (`egor/...`). Живые процессы и туннель без команды не трогает.
- **Роман** — фронтенд, ревью, документация, перезапуски бота по команде Дениса. «Ок» на лог тестов Тимура обязательно до слияния.
- **Тимур** — тесты, слияние, бэкапы, проверка на ПК владельца (игры и система после работ на ПК; диск с локальными моделями и чужой профиль не трогает, кроме явно разрешённой папки).

### 5.2. Ветка → ревью → тесты → слияние → бэкап → перезапуск

1. Своя ветка от текущего `main`, имя вида `egor/...` или `roman/...`.
2. В коммит идёт только нужное: `git add <файл>`, никогда `git add -A`. Сообщение коммита начинается с префикса автора: `Роман: ` или `Егор: `.
3. На `main` нельзя делать rebase, amend и reset.
4. Ревью. Тимур гоняет полный цикл тестов (раздел 4.2) и выкладывает лог. В логе должны быть строки запуска под `unshare -rn`. Роман даёт «ок» только по этому логу.
5. Слияние делает Тимур: `git merge --no-ff`. Без «ок» Романа на лог ветка в `main` не идёт.
6. Бэкап — на обе точки: каталог `backups/` и `C:\LP-backup`. Скрипт `backup.sh [commit]` собирает `git archive` (tar.gz) и git bundle, считает sha256, копирует на ПК и сверяет хеши там. В архив не входят `session.txt`, `*.session`, `config.json`, `settings.json`, `.env`, базы SQLite и их journal. Перед копированием архив прогоняется через `SECRET_RE`; секрет в архиве — код выхода 2. `session.txt` не кладут ни в git, ни в бэкапы, ни в чат.
7. Перезапуск бота — только по команде Дениса, делает Роман, с проверкой PID (см. 4.1). Туннель `lpvk` не перезапускают «заодно».

Кто уходит от этого порядка или сливает без ревью и тестов, снимается с этапа.

### 5.3. Безопасность

- Токены, сессию, ключи и содержимое секретных файлов в чат, в лог и в коммиты не пишут.
- Токен VK в работе — только через `VK_USER_TOKEN`. Ручных запросов в VK нет.
- Тесты — без сети и без токена: `env -u VK_USER_TOKEN unshare -rn ...`.
- Капча или ошибка авторизации — стоп и доклад Денису.
- Панель слушает только `127.0.0.1`, пароля у неё нет.

### 6.3. Текущий баг: команды владельца в VK не выполняются

Факты: события long poll приходят (десятки событий, `vkConnected` true), в `bot.log` нет ни одной строки обработки VK-команды и нет строк `❌ VK` / `⚠️ VK`. Владелец не видит ни правки своего сообщения, ни ответа «команда не найдена».

Диагноз (только чтением). Если сообщение начинается с префикса, у него три исхода: команда выполняется и правит сообщение; ответ «команда не найдена»; исключение и строка `❌ VK: ошибка обработки`. Ни одного из трёх нет, значит сообщения отсеиваются на `if (!msg.text.startsWith(prefix))` в `vk_client.js` (строка 296 в `28534b3`). До `messages.send` / `messages.edit` дело не доходит; ошибки там не глотаются.

Вероятная причина — сам префикс:

- в настройках стоит `‘` (U+2018);
- Telegram и VK сравнивают префикс одинаково, обычным `startsWith`, без нормализации;
- клиент VK на телефоне или другом устройстве может отправлять `'` (U+0027) или `’` (U+2019);
- текст из long poll приходит с HTML-сущностями (`&quot;`, `&amp;`, `&lt;`, переносы), а в `vk_client.js` их нигде не раскодируют. На сам префикс это обычно не влияет, но аргументы команд с кавычками и переносами будут битые.

Какой символ на самом деле первый, покажет диагностическая строка Егора на каждое сообщение владельца: исходящее или нет, hex первого символа, длина, решение (команда / нет префикса / нет доступа). Текст сообщения и peer в лог не пишутся.

План фикса (после этой диагностики, код — у Егора, в своей ветке, процессы не трогать):

1. Перед проверкой префикса раскодировать HTML-сущности в тексте из long poll.
2. Если Денис решит: считать `‘`, `’`, `'` и `ʼ` одним префиксом и в VK, и в Telegram. Это расширение ТЗ, без решения Дениса в код не идёт.
3. Тест: `'команды`, `’команды` и `‘команды` срабатывают, `&quot;` раскодирован, `*команды` игнорируется.

Приёмка только такая: в логе обработана реальная команда владельца и ответ ушёл.
